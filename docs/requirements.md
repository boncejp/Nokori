# Webアプリケーション『Nokori』要件定義書 v2.0

## 1. プロジェクト概要

### 1.1 プロダクトコンセプト

「あといくら使えるか」を1秒で同期する、貯金伴走型Webアプリ。
ユーザーが脳内で行っている「目標からの逆算」と「日々の予算管理」をデジタル化し、精神的余裕（ゆとり）を持ちながら最終目標（貯金）を達成するための意思決定支援ツール。

### 1.2 ターゲットユーザー

明確な貯金目標（例：半年で50万）を持っているが、日々の支出管理にストレスを感じている人。
家計簿アプリの「記録」に挫折し、「今日いくら使っていいか」の直感的なガイドを求めている人。
（※初期リリースは個人利用に特化し、運用検証を行う）

---

## 2. コアロジック（アルゴリズム）

### 2.1 27:00（AM 3:00）リセットロジック

- **定義:** 1日の区切りをAM 3:00（JST基準）に設定。
- **挙動:** 00:00〜02:59の入力は「前日の支出」として論理日付を前日に設定する。03:00にその日の最終収支を締め、余剰金・不足分を確定させる。
- **目的:** 深夜帯の活動を自然に反映させ、翌朝目覚めた時に「最新の今日予算」が提示される状態を作る。

### 2.2 動的日次予算（Dynamic Daily Budget）

**当日予算 D_today:**

```
D_today = 次の給料日までの残り予算 ÷ 次の給料日までの残り日数（当日含む）
```

**リアルタイム表示:**

ダッシュボードでは `D_today - 今日の支出合計` をリアルタイムに表示する。

**翌日以降予算のリアルタイム再計算:**

支出が登録された瞬間に、翌日以降の日次予算予測を即時更新する。

```
D_future = (次の給料日までの残り予算 - 今日の累計支出) ÷ 次の給料日までの残り日数（当日除く）
```

これにより「今日これだけ使ったら明日以降どうなるか」が常にリアルタイムで把握できる。

**日次締め（27:00）:**

27:00の締め処理で当日の余剰金・不足分を確定し、翌日の D_today を正式に決定する。

**余剰の等分分配（日次）:**

1日の終わりに余剰金が出た場合、全額を翌日にスライドさせるのではなく、**次の給料日までの残り日数**で等分して翌日以降の予算に分配する。

### 2.3 月次サイクル余剰金処理（STRICT / YUTORI）

給料日リセット時（月次サイクル終了時）に余剰金が発生した場合、ユーザーが設定したモードで処理する。

| モード | 余剰金の扱い |
|---|---|
| **STRICT** | 余剰金を全額、貯金総額に追加する。翌月の可処分所得は基準値に戻る。 |
| **YUTORI** | 余剰金を翌月の可処分所得に上乗せする。貯金総額への追加は行わない。 |

### 2.4 貯金ノルマ再計算

特別支出等によって貯金総額の変動が発生するたびに、最終目標日までの残り月数で割り、次月以降の「月次貯金ノルマ」を自動再計算する。

```
月次貯金ノルマ = (目標金額 - 現在の貯金総額) ÷ 目標日までの残り月数
```

## 3. 機能要件

### 3.1 認証・初期設定（オンボーディング）

**認証:** Google OAuth / Email 認証（Supabase Auth）。

**初期設定フロー（ステップ順）:**

1. 最終目標金額の入力
2. 達成期限の設定（〇年〇ヵ月の形式で選択）
3. 現在の貯金総額の入力
4. 月収（手取り概算）の入力
5. 給料日の設定（土日祝の前倒し / 後ろ倒し / 固定 ※日本の祝日判定を含む）
6. 固定費合計の入力
7. 光熱費概算の入力（**電気・ガス・水道を個別に設定**）
8. 余剰金処理モードの選択（STRICT / YUTORI）
9. **初回開始予算の入力:** 「現在から次の給料日まで、自由に使える残り予算はいくらですか？」（月途中スタートに対応するためユーザーが自己申告。2回目の給料日リセット以降は自動計算に切り替わる）

**データ移行:** 過去データのインポートは行わず、新規スタートに特化。

### 3.2 ダッシュボード機能

- **メインUI:** 「今日の残り予算」を中央に巨大表示。
- **クイック入力:** 金額入力 → 決定の最小ステップ。
- **属性選択トグル（ヘルプテキスト付き）:**
  - **通常支出:** 当日の可処分予算から差し引く。翌日以降の予算を即時再計算する。
  - **特別支出:** 貯金総額から直接差し引く（当日・翌日以降の予算に影響しない）。入力後、月次貯金ノルマを自動再計算する。
  - **光熱費（電気 / ガス / 水道）:** 実額入力時、各項目の概算との差額を即座に算出し、当月残り予算に即時反映する。実額 < 概算の場合は予算増、実額 > 概算の場合は予算減。
- **翌日以降予算プレビュー:** 支出登録のたびにリアルタイム更新される「明日以降の予測日次予算」を表示する。
- **警告表示:** 当日予算超過時、画面全体に赤系統の警告色を適用。

### 3.3 履歴管理機能

- **支出リスト:** 当月の支出を時系列で表示。
- **編集・削除:** スワイプによる削除。削除時は当日予算および翌日以降の予算を即時再計算。

### 3.4 設定・シミュレーション機能

- **動的シミュレーション:** 達成期限や固定費を変更した際、確定前に「今日の日次予算」への影響をリアルタイムにプレビュー。
- **データ初期化:** 全データを削除し、初期設定からやり直す機能。

## 4. 非機能要件

### 4.1 UI/UX デザイン

- **ビジュアルテーマ:** Apple風ミニマリズム。
- **カラー:** ネイビー（#001F3F等）とホワイト。
- **タイポグラフィ:** モダンなサンセリフ体（SF Pro / Inter）。
- **アクセシビリティ:** 各スイッチに挙動を説明するスタイリッシュなヘルプテキスト（ツールチップ）を実装。

### 4.2 技術特性

- **Webアプリ (PWA):** ホーム画面追加、基本的なキャッシュによる高速化（オフライン時の完全な入力データDB同期はV2拡張とする）。
- **通知:** 入力忘れ防止リマインド、27:00締め後の結果サマリー通知。
- **パフォーマンス:** 楽観的UI更新によるゼロ・レイテンシ体験。

---

## 5. 画面定義

- **Dashboard:** 今日の残り予算表示、テンキー入力、属性トグル（通常 / 特別 / 光熱費）、翌日以降予算プレビュー。
- **History:** 支出一覧、スワイプ削除。
- **Settings:** マスター設定（光熱費概算を電気・ガス・水道で個別設定）、余剰金処理モード選択（STRICT / YUTORI）、期間シミュレーション、データ初期化。

---

## 6. 技術スタック

- **Frontend:** Next.js (App Router), Tailwind CSS
- **Backend/DB:** TypeScript, Supabase (PostgreSQL, Auth)、RLS（Row Level Security）による認可
- **DB Client:** `@supabase/ssr`（Next.js App Router対応、RLSを適切に通過するクライアント）
- **State Management:** Zustand（計算ロジックの集中管理）
- **PWA:** next-pwa
